# 老系统维修导入

支持无锡“维修账单”的手动单向同步。2026-10-08 起流程为：**拉取到本地暂存 → 本地筛选与管理 → 勾选记录 → 确认同步到订单系统**。暂存使用独立 `legacy_cache*` 表，不创建工单、客户、设备、财务或库存记录。原始 23 个字段加密持久化，原先已有预览的快照也会复用到暂存库。

## 使用步骤

1. 更新后端依赖并构建前端，再重启新系统服务。启动时自动添加 `legacy_*` 表和接管保护，不将旧库业务数据直接迁移到新库。
2. 进入 **老系统导入 → 连接设置**，填写来源 API 地址、账号和密码，保存后测试连接。来源固定为无锡；已配置的来源地址不能通过覆盖配置替换。
3. 进入 **数据暂存**，点击“首次拉取到本地”初始化完整暂存库。此后点击“增量拉取到本地”，不会每次重新下载全部账单。已有旧预览可能仅覆盖某个日期范围，因此复用旧快照后仍需要一次完整初始化。
4. 在暂存库搜索旧 ID、客户、机型或工程师，查看完整字段，填写本地管理备注，排除暂不导入的记录；可恢复已排除记录。单条“刷新此条”只读取该账单，适用于未维护更新时间的旧记录。管理备注不会改写来源字段。
5. 进入 **同步审核**，输入日期范围或旧账单 ID，点击“从本地生成预览”。全部留空使用本地全部未排除记录；筛选、状态及员工映射、重复身份检查均在本地执行，不连接旧系统。通过“调整映射规则”进入 **映射规则**，配置对应员工与状态，点击“保存并去重新预览”返回同步审核。
6. 新库已有同一业务时，先选择目标工单建立关联。关联现有工单时默认由新系统接管，保留已有项目和流水；关联后重新预览。
7. 明确勾选要同步的记录，点击“确认同步”。未勾选的记录跳过并继续留在暂存库；已跳过记录通过新预览重新选择。每次执行前自动建立 SQLite 一致性备份，只复核选中来源行、这些 ID 在来源的唯一性及目标版本。异常行独立记录，失败可重试；源数据、暂存、映射或目标变化时先刷新暂存并重新预览。旧版批次需重新生成本地预览。
8. 历史单在 **老系统导入 → 导入记录** 查看，历史金额独立统计。在修单可由管理员或老板确认阶段、工程师、客户设备及历史已收/期初待收金额后接管。两个金额均必须明确填写，零与未知不同。

## 导航与交互（2026-10-10）

老系统导入从系统设置中独立为一级导航，按操作目的拆成六个页面：

| 页面 | 职责 | 后续操作 |
| --- | --- | --- |
| 导入概览 | 展示连接、暂存规模、最近拉取进度、同步批次与失败原因 | 查看任务直接进入该批次审核；图片复制失败可单独重试 |
| 数据暂存 | 首次/增量拉取、全量核对、搜索、备注、排除与恢复、单条刷新 | 整理后进入同步审核 |
| 映射规则 | 根据选定批次识别来源工程师及状态组合，维护对应关系 | 保存后返回同步审核，重新生成预览 |
| 同步审核 | 筛选、生成预览、核对差异、关联已有工单、勾选执行及失败重试 | 查看导入记录 |
| 导入记录 | 查询已导入的历史与在修记录、查看字段、接管及打开工单详情 | 从工单详情返回导入记录 |
| 连接设置 | 配置与测试来源连接 | 进入数据暂存 |

首次使用：连接设置 → 数据暂存 → 同步审核；若预览发现员工或状态需要调整，进入映射规则，保存后回到同步审核重新生成预览。日常使用可从导入概览继续任务，或直接增量拉取。

切换子页面时保留当前批次、预览筛选与跨页勾选。选择另一个批次后清空勾选，并恢复该批次原始筛选条件；修改映射或关联后提示重新预览。暂存版本或来源配置版本变化时禁用旧预览的执行入口。确认同步与失败重试使用不同的确认说明，未勾选时禁止首次执行。查询记录时不加载后台管理表单和批次明细；普通员工仅显示导入记录入口，管理员和老板显示全部页面。

## 数据口径

- 每张来源账单唯一对应一张新工单。客户姓名、重复串号、短占位串号不作为自动合并依据。
- 原始快照加密保存全部字段，包括 NULL、空字符串、零、原时间及锁屏密码。普通预览、列表与日志遮蔽锁屏密码；有权查看工单的人可单独读取，并记录审计操作。
- 历史报价、成本、利润、人工费和三个配件槽位保留原口径。同步不生成维修项目、SKU、预留、扣库、收付款、虚构流程日志或工程师绩效。
- 期初待收是新系统接管后的收费基数，历史已收金额只作追溯，不补造流水。接管后新增的报价调整按正常业务处理。
- 未接管工单在导入查询中查看；正常工单池、设备经营统计和客户欠款排除这些记录。历史完成单保持只读，后续返修另开新单。
- “维修完成 / 已结账/已取机”和已验证的“维修完成 / 待维修”识别为历史完成；“待结账 / 待维修”识别为已交付、待接管继续办理；其余组合按既有规则识别。未知组合进入待确认，不凭空推断收款、交付或结单时间。
- 当前默认规则把“待维修”识别为待接管在修单。实际来源还有“同行挂帐”“无成本”“已退机”等组合，需根据店内语义确认后映射。

## 图片与任务

图片原引用永久保存在原始快照，复制任务在账单提交后执行。支持同源 HTTPS 地址、相对路径、JSON 文本数组、换行或分号分隔的引用。复制支持 PNG/JPEG/GIF/WebP，单文件最多 10MB；其他格式记录失败原因，人工确认后处理。

附件按来源引用和内容去重，失败可单独重试。接管后同步及附件重试不再修改新工单附件。已下载文件使用内容哈希命名，反复重试不增加照片记录。

来源同一时间只允许一个读取、执行或附件任务。批次、明细和结果持久化；服务重启将运行中任务标记为中断，释放来源占用。已完成预览的批次可重试，未完成读取的批次重新读取。

首次拉取使用 rowid 稳定分页，每页最多 500 条，扫描前后核对数量及边界。日常增量使用新增 rowid、有效更新时间水位及两天重叠窗口，每次额外轮换核验最多 500 条历史记录。水位在成功完成任务后推进，失败保留已接收页面和旧水位；重试幂等。未维护或格式异常的更新时间不作为可靠变更通知，这些记录靠单条刷新、轮换核验或手动全量核对发现。轮换完成整库需要多次拉取，首次初始化和明确选择全量核对才读取完整业务字段。

来源删除通过已核验的轮换页、单条刷新或成功的全量核对标记；暂存和新工单保留。来源 rowid 上界回退时停止增量并要求核对来源身份。旧系统没有变更日志和跨请求快照接口，增量检测不承诺即时发现所有无时间戳历史修改。确认同步时按最多 500 条选中记录复核原值和唯一 ID，不重新扫描全库；本地暂存版本、目标版本和单行事务防止过期预览覆盖数据。远端在复核到本地提交之间的再次编辑仍由下次同步识别。

## 备份与来源维护

执行备份位于新库旁的 `legacy_backups/`。使用 SQLite Backup API，适用于开启 WAL 的数据库；备份失败则整个执行任务停止。

连接凭据及原始快照使用 Fernet 加密。默认密钥保存在新库旁的 `.legacy.key` 文件，也可通过环境变量 `MIS_LEGACY_KEY` 指定 Fernet 密钥。密钥与数据库分别妥善备份，不加入 Git。恢复数据库时必须恢复同一密钥。

恢复、替换或回退老系统数据库后，先停止同步并核对来源身份、旧 ID 对应和新旧值，重新读取预览；不要将一个新来源沿用旧来源对应关系。首期没有来源重置按钮，需由维护人员审核后创建独立来源迁移方案。

恢复新库备份仅在维护窗口停服后进行。恢复前备份当前新库；禁止在线恢复覆盖期间正常营业写入的数据。

## 已验证的小程序状态流程（2026-10-10）

通过订单 20436 的逐步操作、确认框和来源数据库只读查询，确认当前小程序流程如下：

| 操作 | 备注 | 付款方式 | 来源更新时间 | 默认导入处理 |
| --- | --- | --- | --- | --- |
| 新建 | 待维修 | 待维修 | 17:44:22 | 接管后继续办理 / 已开单 |
| 已修好 | 待取机 | 待维修 | 17:49:09 | 接管后继续办理 / 待交付 |
| 已取机 | 待结账 | 待维修 | 17:51:12 | 接管后继续办理 / 已交付 |
| 已收款 | 维修完成 | 待维修 | 17:53:02 | 仅作历史查询 / 已结单 |

三个按钮各只改变这 23 个原始字段中的“备注”和“更新时间”；付款方式一直保留“待维修”。该流程中“维修完成”表示收款确认后的结束阶段，而“已修好”进入的是“待取机”。新建时已有解决方案、利润和人工费，字段有值不构成维修完成的证据。

本次仅新增“待结账 / 待维修”和修正“维修完成 / 待维修”的默认识别；其他组合沿用原规则，人工保存的映射仍优先。同行挂帐、无成本、已退机及其他历史入口的含义尚待核实，不根据本次单一路径推断。上述确认不代表核验真实资金到账，也不补造收款流水、结单时间或库存流水。

旧预览须重新生成后才可执行。未接管且曾按旧规则导入的受影响记录，会在新预览中显示更新，仍需勾选确认；已接管记录保持新系统维护。此次代码更新不直接改写现有业务数据。
